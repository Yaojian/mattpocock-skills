# 向导 (Wizard)

**向导 (wizard)** 是一个 bash 脚本，一步一步带真人走完手动流程：手工做很烦，每次重新给 AI 讲一遍也很烦。它逐个打开 URL，精确说明点哪里、复制什么，收回填入的值，写到它们该去的地方（`.env`、GitHub secret），每阶段确认，并显示还剩多少阶段。可能是配置第三方服务、跑一次性迁移，或把项目从一个状态搬到另一个状态。

好用的交互体验已由 [template.sh](template.sh) 解决：分阶段进度、确认门、跨平台打开 URL（含 WSL）、隐藏式 secret 输入、幂等的 `.env` 写入、`gh secret`/`gh variable` 写入，以及收尾总结。**你的工作只是划定流程范围并编写它的阶段。** `STAGES` 标记之上的库在每个向导里都一样；一致性正是目的：绝不手工改它。

向导默认用完即弃：为跑一次而构建，放在临时或 `scripts/` 路径，跑完删除。只有用户想要可重复的、值得住在仓库里的 setup 路径时才提交。

## 流程

### 1. 划定流程范围

弄清人类必须走的每个手动步骤，以及沿途产出的每个值。先读仓库，不要冷启动发问：

- setup 类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 迁移或状态切换类：当前状态、目标状态，以及之间的不可逆操作。

然后把有序的阶段列表和每个阶段产出的值给用户看并确认：他们可以增删或重排。

**完成标准：** 每个阶段按序命名，对每个收集的值都知道 (a) 人类从哪里拿到它，(b) 写到哪里（`.env`、GitHub secret、两者，或哪里都不写；有些阶段是纯动作），(c) 是 secret（隐藏输入）还是公开值。

### 2. 画出每个阶段的路径

为每个阶段写出人类走的精确路径：打开哪个 URL，在那里做什么，值显示在哪里，填进哪个变量。例如“Dashboard → Developers → API keys → Reveal test key → copy”。凡是不确定当前 UI 或确切命令的地方，直说并问用户或查文档：绝不编造可能不存在的步骤。

**完成标准：** 每个阶段都能对应到陌生人可照着走的具体指令。

### 3. 编写向导

把 `template.sh` 复制到目标路径。把示例阶段替换为每步一个 `stage`，按依赖排序。用库函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为你写的阶段数。

守住模板立下的标准：先打开 URL 再要它的值，secret 一律用 `ask_secret`，每个持久化的值都用 `write_env`，只有 CI 真正需要的值才用 `set_secret`，不可逆操作前用 `confirm`。每个 `stage` 会清屏，只显示当前步骤：一个阶段只做一件聚焦的事，让人类需要的东西不被滚出屏幕。标记之上的库不要动。

### 4. 验证并交接

- `bash -n <script>`；有 `shellcheck` 就跑一遍。
- `chmod +x <script>`。
- 不要自己端到端运行它：它会打开浏览器并阻塞等待人类输入。改为静态走查：步骤 1 的每个值都被收集并落到步骤 1 说的地方，每个 `set_secret` 的名字与 CI 中的 `secrets.*` 引用精确一致。
- 告诉用户怎么运行它。如果是可重复的 setup 路径，提交它并从 README 链接过去，让下一个人直接跑脚本而不是问 AI。
