# 解决合并冲突

1. **查看合并或变基的当前状态**。检查 git 历史和冲突文件。

2. **为每个冲突找到一手来源**。深入理解每次修改为什么会发生，当初的意图是什么。阅读提交信息，查看 PR，查看原始问题或工单（issue/ticket）。

3. **逐个解决每个冲突块。** 尽量保留双方的意图。如果不兼容，就选择符合本次合并既定目标的一方，并记下权衡。**不要**凭空发明新行为。必须解决到底，绝不 `--abort`。

4. 找到项目的**自动化检查**并运行，通常是先类型检查，再测试，再格式化。修复合并破坏的任何东西。

5. **完成合并或变基。** 暂存全部内容并提交。如果是变基，就持续推进变基流程，直到所有提交都变基完成。
