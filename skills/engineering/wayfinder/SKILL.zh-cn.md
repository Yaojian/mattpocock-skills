# Wayfinder

一个宽松的想法送到了，太大，单个智能体会话装不下，还裹在迷雾里：从这里到**目的地 (destination)** 的路还看不见。寻路 (wayfinding) 要找的是这条路，而不是向目的地冲锋。该技能把这条路画成仓库 issue 跟踪器上的一张**共享地图 (shared map)**，再把它的**决策工单 (decision tickets)**（解决方式是决策、而不是待执行的构建切片的问题）逐个解决，直到路线清晰。

目的地因工作而异，命名它是画地图的第一步：它决定每张工单的形状。它可能是一份待交接和迭代的规格说明，一个规划开始前要锁定的决策，或数据结构迁移这类就地完成的改动。地图与领域无关：工程工作、课程内容，只要符合这个形状都适用。

## 只规划，不动手

Wayfinder 默认只做**规划**：每张工单解决一个决策，当开工前再也没有待做的决策、路线已经清晰时，地图就算完成。想直接动手写的冲动，通常说明你已走到地图边缘，该交接了。某项工作可以在它的 **Notes** 中覆盖这一点，把执行也纳入地图，但没有覆盖时，只产出决策，不产出交付物。

## 用名字引用

每张地图和工单都是 issue，所以它有**名字**：即标题。在人类阅读的一切内容（叙述、地图的 Decisions-so-far）中，用名字引用它，绝不用裸 id、数字或 slug。一串 `#42, #43, #44` 没法读，名字一眼可读。id 和 URL 并没有消失；名字包裹着它的链接，只是它们藏在名字*里面*，从不代替名字出现。

## 地图

地图是本仓库 issue 跟踪器上的单个 issue，标签为 `wayfinder:map`，是标准产物。它的工单是该地图的子 issue。

地图是**索引**，不是仓库。它列出已做的决策，指向持有细节的工单；一个决策只住在一个地方，即它的工单，所以地图从不复述，只写梗概加链接。

**地图、子工单、阻塞关系和前沿查询在物理上存在哪里，取决于跟踪器。** issue 跟踪器应该已经提供给你。如果没有，请用户运行 `/setup-matt-pocock-skills`。查阅跟踪器文档的 "Wayfinding operations" 一节，了解*本*仓库如何表达它们。如果完全没有提供跟踪器，默认使用本地 markdown 跟踪器。

### 地图正文

整张地图的低分辨率视图，每个会话加载一次。开放工单**不**列出：它们是开放的子 issue，用查询找到。

```markdown
## Destination

<what reaching the end of this map looks like: the spec, decision, or change this effort is finding its way to. One or two lines; every session orients to it before choosing a ticket.>

## Notes

<domain; skills every session should consult; standing preferences for this effort>

## Decisions so far

<!-- the index: one line per closed ticket, enough to judge relevance, then zoom the link for the detail the ticket holds -->

- [<closed ticket title>](link): <one-line gist of the answer>

## Not yet specified

<!-- see "Fog of war": in-scope fog you can't ticket yet; graduates as the frontier advances -->

## Out of scope

<!-- see "Out of scope": work ruled beyond the destination; closed, never graduates -->
```

### 工单

每张工单是地图的**子 issue**；跟踪器的 issue id 即其身份。工单正文即问题，大小以一个 100K 词元智能体会话为限：

```markdown
## Question

<the decision or investigation this ticket resolves>
```

每张工单带一个 `wayfinder:<type>` 标签，取值为 `research`、`prototype`、`grilling`、`task` 之一（见[工单类型](#ticket-types)）。

一个会话**认领**工单的方式是把它指派给推动地图的开发者，**第一步**，在任何工作之前，所以并行会话会跳过它。指派关系*就是*认领：开放且未指派的工单即未认领。

阻塞关系使用跟踪器的**原生**依赖关系：这很关键，因为前沿会直接在跟踪器自己的界面里*可视化*渲染，人不用打开地图就能看到哪些可拿。只有缺乏原生阻塞关系的跟踪器才回退到正文约定。当阻塞某工单的所有工单都关闭时，该工单即**未阻塞**；**前沿 (frontier)** 是开放、未阻塞、未认领的子工单集合，即已知世界的边缘。

答案不放在正文里；在解决时记录（见[走通地图](#work-through-the-map)）。解决工单时产生的资产从 issue 链接出去，不粘贴进来。

## 工单类型

每张工单要么是 **HITL**（人在回路，与真人*一起*工作，真人亲自发言），要么是 **AFK**（智能体独自推动）。HITL 工单只能通过实时交流解决；智能体绝不代替人类的那一侧发言（自问自答的追问智能体已经违规）。

- **Research** (AFK)：阅读文档、第三方 API 或知识库等本地资源，挖出某个决策等待的事实。当需要当前工作目录之外的知识时使用。解决方式是派子智能体调用 Skill 工具加载 "research"。
- **Prototype** (HITL)：调用 Skill 工具加载 "prototype"，做一个便宜、粗糙、具体的可反应物（大纲、粗稿、桩，或界面/逻辑代码），提高讨论的保真度，并把原型作为资产链接出去。当关键问题是“应该长什么样”或“行为应该如何”时使用。
- **Grilling** (HITL)：对话。默认情况。调用 Skill 工具两次，分别加载 "grilling" 和 "domain-modeling"。
- **Task** (HITL 或 AFK)：在*决策*能做出之前必须发生的手工活：没什么可决策、可原型、可研究的，但讨论被它卡住，直到它做完。比如注册某个服务以便评审它的 API，开通访问权限，搬运数据以便看到它的形状。这是唯一*动手*而不做决策的类型，它的席位靠为决策扫清阻塞赢得，而不是靠交付目的地。智能体能独自推动的就独自推动 (AFK)，否则给人类一份精确的清单 (HITL)。做完即解决；答案记录做了什么，以及后续工单依赖的事实（凭证位置、新 URL、行数）。

## 战争迷雾

地图*故意*不完整：看不清的东西不要画。活跃工单之外是**战争迷雾 (fog of war)**：能感觉到要来、但还定不下来的决策和调查，因为它们挂在尚未解决的问题上。解决一张工单，就驱散它前方的迷雾，把现在可描述的东西逐个毕业为新工单，直到通往目的地的路清晰，再也没有工单剩下。

地图的 **Not yet specified** 一节就是写下这种模糊视野的地方：疑似的问题，稍后回看的区域。它是朝向目的地的未发现前沿：都在范围内，只是还不够清晰到能写成工单。写多松或多细都可以，看视野允许；它同时是给协作者看的路标，指示工作朝哪走。

**迷雾还是工单？** 检验标准是现在能否精确陈述问题，*不是*现在能否回答它。

- **能精确陈述时写工单**，即使它被阻塞、现在还动不了。
- **还不能那样清晰时记入 Not yet specified**。不要把迷雾预切成工单大小的块：它比工单粗，一片迷雾在前沿到达后可能毕业为多张工单，也可能一张都没有。

**Not yet specified** 排除已决策的（Decisions so far）、已是活跃工单的，以及范围之外的（下一节）。

## 范围之外

迷雾只会朝目的地聚集。目的地划定范围，所以超出它的工作是**范围之外 (out of scope)**：它不是迷雾，也不属于 **Not yet specified**。它在地图上有自己的 **Out of scope** 一节：经有意识排除出*本次*工作的内容。范围而非清晰度决定它落在这里。

范围之外的工作永不毕业（前沿止于目的地），只有重画目的地时才回来，那也是作为新的工作，而不是恢复旧的。

把某事排除出范围是划定范围的动作，不是路线上的一步。当一张已存在的工单实际坐在目的地之外（画地图时误划进来，或被某个解决结果暴露），**关闭它**（已关闭的工单明确不在前沿上），在 **Out of scope** 一节留一行：梗概加为什么超出范围，并链接已关闭的工单。它不进入 **Decisions so far**，后者记录实际走过的路线；范围边界不是路线上的一步。

## 调用

两种模式。无论哪种，**每个会话解决不超过一张工单**，研究 (research) 工单除外。

### 画地图

用户带着一个宽松的想法调用。

1. **命名目的地。** 调用 Skill 工具两次，分别加载 "grilling" 和 "domain-modeling"，定下这张地图要找到的东西：规格说明、决策或改动。目的地划定范围，所以先定它。
2. **画出前沿。** 再追问一轮，这次**广度优先**：铺满整个空间找开放决策和现在可拿的第一步，而不是在任一线索上深挖。**如果没有发现迷雾**（通往目的地的路已经清晰，全程小到一个会话装得下），就不需要地图。停下，问用户想怎么继续。
3. **创建地图**（标签 `wayfinder:map`）：填好 Destination 和 Notes，Decisions-so-far 为空，迷雾草记进 **Not yet specified**。
4. **把现在可描述的创建为工单**，作为地图的子 issue，再**分两步**连阻塞边（issue 需要先有 id 才能互相引用）。连边后它们自然分成前沿和被阻塞的；还不能描述的留在迷雾里：即 **Not yet specified** 一节。
5. **派出研究子智能体。** 对刚创建的每张 `research` 工单，起一个子智能体调用 Skill 工具加载 "research" 并行解决，把发现记在一次性的 `research/<name>` 分支上，从工单挂一个上下文指针过去。
6. 停下：画地图是一个会话的工作；不顺手解决。

### 走通地图

用户带着一张地图（URL 或编号）调用。工单**可选**：不给工单时，由你挑选下一个决策，而不是用户。

1. 加载**地图**：低分辨率视图，不加载每张工单的正文。
2. 选工单。用户点了名就用它。否则按顺序拿第一张前沿工单。**认领它**：在任何工作之前先把它指派给自己。
3. 解决它。**按需放大**：取任何相关或已关闭工单的完整正文；调用 Skill 工具加载 `## Notes` 块点名的技能。拿不准时，调用 Skill 工具两次，分别加载 "grilling" 和 "domain-modeling"。
4. 记录解决结果：把答案作为**解决评论**发布，**关闭** issue，并在地图的 Decisions-so-far **追加一个上下文指针**。
5. 新增浮现的工单（先创建再连边）；把答案已使其可描述的迷雾毕业，从 **Not yet specified** 清掉已毕业的块，让它只作为新工单存在。如果答案显示某张工单（这张或其他）坐在目的地之外，**把它划出范围**，而不是在路线上解决它。如果决策推翻了地图的其他部分，更新或删除那些工单。

用户可能并行跑未阻塞的工单，所以要有其他会话同时改跟踪器的预期。
