你已拿到一份规格说明，它应附带若干工单，说明如何实现这份规格说明。

目标是在单个分支上实现整份规格说明，并产出一个 PR。

工单不是步骤清单，而是一张带阻塞关系的**任务图**，这意味着总有一批**前沿**工单处于可领取状态。

与子智能体的来往沟通应尽量精简，主要经由**上下文指针**沟通：指向规格说明、工单、调研笔记和之前的提交。指针已能取到的信息不要重复。

**实现者子智能体**应尽量在后台运行，以实现**最大并发**。

## 步骤

1. 通读规格说明和工单，读到能理解任务图为止。

2. （可选）用**探索子智能体**完成工单要求的前期探索，包括相关代码文件或外部文档。确保探索子智能体能存文件，它的 Markdown 笔记应存在仓库之外的目录，让所有后续子智能体都能取到。这样**实现者子智能体**就能专注实现，不必再做探索。

3. 建分支，开草稿 PR，该 PR 应标记为关闭（closing）规格说明 issue 和相关工单。

4. 用**实现者子智能体**实现每个工单，每个实现者子智能体在自己的 worktree 和自己的分支上工作。

5. 某个**实现者子智能体**完成后，用**合并者子智能体**把它的工作合入 PR 分支。

6. 如果这改变了可用工单的**前沿**，就启动更多**实现者子智能体**处理新工单，以保持最大并发。

7. 所有工单完成后，在 PR 分支上跑 /code-review，把评审提出的问题集中在一个**实现者子智能体**里修完。

8. 把 PR 标记为可评审。

9. 清理所有**实现者子智能体**的 worktree。
