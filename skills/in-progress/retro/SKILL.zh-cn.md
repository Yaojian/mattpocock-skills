用户要求做一次**复盘（retrospective）**。你正在为编码智能体的**环境**提出改进建议，以优化未来的运行效果。

## 步骤

1. 通过 Skill 工具调用 `writing-for-agents`，获取写作风格指南。

2. 阅读用户指定的会话的一手来源。这可能意味着要在本机搜索会话日志。如果用户没有指定会话，默认复盘当前会话。

3. 在以下类别中寻找改进点。

- **导航**：智能体找到正确文件有多容易？文件之间是否存在隐藏依赖？加一个**导航指针**会不会更省事？*适用情形*：会话花了很长时间才找到某条信息。
- **自动化检查**：有没有自动化检查可以捕获智能体犯过的错误？Lint、类型检查、测试、文件系统检查？先读该仓库自己的检查命令（`package.json`/构建工具中的 `lint`/`check` 脚本、CI 工作流），这样真正的发现应该是“已有但未接线或已静默损坏的检查”，而不是重复造轮子。一个没有任何**防护栏**的仓库（既没有 pre-commit 钩子，也没有运行 lint/typecheck/test 命令的 CI 任务）本身就是一个发现：无 lint 的仓库是长期存在的错失机会，而不是中性默认状态。*适用情形*：智能体犯了自动化检查本可以捕获的错误，或者仓库完全没有防护栏。
- **编码规范**：是否应该给**复核智能体**加一条新规则来强制执行？是否应该删除或澄清某条现有规则？先对违规分类：**机械类**违规（固定的语法模式、禁用的 API、导入形态、文件位置规则）一律做成确定性检查：在仓库自带的 linter 中加自定义规则，或加新的 pre-commit 钩子，或加新的 CI 任务，具体选仓库语言和现有防护栏下成本最低的一种。默认优先构建检查，而不是撰写规则。把 `CODING_STANDARDS.md` 留给真正的**判断类**问题（跨文件一致性、“与周围风格保持一致”、任何防护栏都无法替代的内容）。*适用情形*：复核智能体漏掉了某个错误。
- **全局 AGENTS.md**：有没有应该搬到编码规范（或自动化检查）中的引导指令？*适用情形*：仓库内或用户全局范围的 AGENTS.md 文件特别庞大。
- **工具开销**：智能体是否发起了本可精简的高开销工具调用？有没有特别消耗词元的自定义工具（CLI、MCP）？*适用情形*：智能体发起过高开销的工具调用。
- **空转指令**：在引导文件中寻找不改变智能体行为的指令。*适用情形*：引导文件庞大而难维护。
- **信息获取**：寻找扩大智能体信息获取能力的机会。例如接出开发服务器日志、对第三方服务的只读访问。*适用情形*：智能体拿不到某条关键信息。

4. 按严重程度排序，把这些候选项呈现给用户。

## 参考

### 实现与复核

记住所有工作都经过两个阶段：实现和复核。实现智能体承受最大的**上下文压力**。它负责探索、写代码和调试失败。

复核智能体承受最小的上下文压力，它收到的是 diff，不需要探索。它通常不需要写代码或调试。

因此，复核智能体应该负责执行编码规范，而不是实现智能体。

### 文件

你可以在仓库中访问以下几类文件：

- `CLAUDE.md`/`AGENTS.md`：这些文件会被推送到在该仓库中工作的任何智能体的上下文窗口中。要极其克制地使用，通常只放指向其他文件的**导航指针**。
- `CODING_STANDARDS.md`：该文件在复核阶段读取，而不是实现阶段。如果规范文件超过 1,000 行，就加入指向 docs 目录的**导航指针**。
- Docs：把 docs 用作被其他文件指向的引用文件。写新文档之前先找现有文档。
- 技能：把技能用于文档（因为技能描述会进入智能体的上下文窗口），或用于用户调用的命令。遵循 `writing-for-agents` 技能中的建议。
