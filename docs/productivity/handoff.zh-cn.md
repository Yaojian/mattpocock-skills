## 它能做什么

`handoff` 会把你所在的对话压缩成一份**交接文档 (handoff document)**：一个单独的 Markdown 文件，写入你操作系统的临时目录，而不是工作区。新的[智能体 (agent)](https://www.aihero.dev/ai-coding-dictionary/agent)读到它，就可以接手继续工作。

它带来的是**可移植性 (portability)**，而不是压缩。因此这个技能比听起来要窄。只有当工作必须**流动**时，你才需要这个文件：换到新的[运行环境 (harness)](https://www.aihero.dev/ai-coding-dictionary/harness)、新的目录、同事，或者想分叉出一个并行处理的子任务。如果没有东西需要流动，就不需要交接：在[会话 (session)](https://www.aihero.dev/ai-coding-dictionary/session)中继续、`/clear`、[子智能体 (subagent)](https://www.aihero.dev/ai-coding-dictionary/subagent) 和 `/compact` 就能覆盖普通的阶段收尾场景，而且 `/compact` 比这个技能更常用。

## 何时使用

输入 `/handoff` 即可调用，智能体不会自行调用。请附上一句说明，讲清下一次会话的目标，文档就会围绕这个目标来写。

全部触发场景只有四种：

| 场景 | 为什么需要文件 |
| --- | --- |
| 更换运行环境（Claude 换到 Codex） | 新环境看不到旧的[上下文 (context)](https://www.aihero.dev/ai-coding-dictionary/context) |
| 换到不同目录或仓库 | 常见情况是原型目录 |
| 把工作发给同事 | 对方需要一份可读的材料 |
| 从当前阶段中分叉出一个子任务 | 你继续手头工作，第二个智能体接手分叉任务 |

除此之外的其他情况（同一个运行环境、同一个目录，你已经完成[追问 (grilling)](https://www.aihero.dev/ai-coding-dictionary/grilling)并要进入实现），都应该用 `/compact`。[ask-matt](https://aihero.dev/skills-ask-matt) 在阶段边界处整理了全部五个选项的有序决策树。

## 分支是最容易被忽略的用法

这个技能的描述读起来像是会话恢复：写一份总结，在这里结束，在那里恢复。这样理解，它看起来像是更弱的 `/compact`，所以很容易被略过。真正值得了解的是分叉场景。你**留在当前会话**，把已积累的上下文复制一份，交给第二个并行工作的智能体。

[prototype](https://aihero.dev/skills-prototype) 的迂回用法就是这样。你正在深入讨论设计，遇到一个只有跑代码才能回答的问题，又不想把已经建立的讨论主线耗费在验证上。这时交接给一个原型会话，拿到答案，再把答案带回来，并在原来的主线中引用它。两次跨越，一次持续的对话，不需要重新解释任何东西。

阶段边界处的五个选项中，有三个分别保留不同的东西：`/compact` 保留你的意图，`/clear` 什么都不保留，`/handoff` 保留工作流动的能力。

## 哪些内容会传递，哪些不会

文档携带当前主线（正在进行什么、为什么做、下一步是什么），再加一个**推荐技能 (suggested skills)** 小节，写明下一个智能体应该使用哪些技能。写入之前会先隐去密钥。

它有意不携带任何已经落字的内容。规格文档、计划、ADR、议题、提交记录和差异都只用路径或 URL 引用，绝不复制全文。这样文件保持很小，确定的细节也只保留在一处，不会出现两处逐渐不一致的情况。

## 常见问题

**用 handoff 还是 compact？**
除非有东西需要流动，否则用 `/compact`。留在同一个任务上继续推进属于 compact，而不是 handoff：同一个运行环境、同一个目录、你需要留在循环里，这是阶段边界决策树在多数日子里的落点。`/handoff` 的优势不在于总结得更好，而在于结果是一个文件，可以带到 `/compact` 到不了的地方。

**compact、clear 和 handoff 到底有什么区别？**
三者保留的东西不同。`/compact` 把当前上下文压缩后，让你在全新窗口中继续：意图得以保留。`/clear` 清空窗口，从零开始：当身后的一切都可丢弃时适用，如果并非如此，这个操作是不可逆的。`/handoff` 写出一个可携带的文件：工作可以在换地方后存续。注意，三者都是把**[一手来源 (primary source)](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（实际发生的对话）变成**[二手来源 (secondary source)](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（对它的总结）。只有继续对话才不做这种转换，这也是为什么要先排除继续对话这个选项。

**我的交接文件去哪了？**
在临时目录里，这是该技能反馈最多的 friction：路径很长，各操作系统不同，在 Windows 上智能体有时要试几次才能找对。请在继续之前先要回路径并保存好。放在临时目录是有意的：交接文件是中转文档，不是需要长期维护的产物。它也不是持久化的，见下一个问题。

**我的交接文件在两次会话之间消失了。**
有些环境会在会话之间清理临时目录（有报告称 Codex 会这样），`/private/tmp` 在重启后也会清空。如果下一次会话不是一小时内就开始，或者要换运行环境，文件写好后请立刻自己复制到持久位置。同样的道理也适用于文档**指向**的东西：如果分发内容引用了临时目录里的其他文件，下一个智能体就跟不下去了。

**实际怎么把它交给下一个智能体？**
打开全新的会话，把路径指给它：读这个文件，然后继续。请直接指向文件，而不是把总结粘贴进 shell 命令：包含反引号或 `$(...)` 的总结在插值进 `claude "<summary>"` 时会被破坏，常见的失败是静默截断而不是报错，新智能体就会拿着一份悄悄缺了一块的简报开工。

**这和 `/branch`、`--fork-session` 或内置的 `/handoff` 是一回事吗？**
类似，但不相同，而且 `/branch` 在这里不是已发布的技能，`/handoff` 才是规范名称。分叉会继承上下文的精确副本，而这个技能产出的是针对明确的下一个任务的**定向**压缩，落在一个文件里。在分叉可行的地方（同一台机器、同一运行环境、同一目录），分叉更省事。一旦目标是分叉到不了的地方，文件就胜出了。

**什么时候该放进 `CLAUDE.md` 而不是交接文档？**
问一句：下个月还成立吗？`CLAUDE.md` 是关于项目的常设上下文，每次会话都会加载，不管当次是否相关。交接文档只关乎一项进行中的工作，工作落地它就失效。反复需要重新解释的事实是 `CLAUDE.md` 的问题，做到一半的任务才是交接文档的问题。

**它只记录了做什么，没记录为什么。**
这是合理且反复出现的批评。有两件事能缓解。调用时传入说明（讲清下一次会话的目标），这样与**那个目标**相关的推理会被保留，而不是被压平。另外要留意会话中从未真正验证过的自信断言：“X 还没做”、“Y 做完了”。下一个智能体会把文档当作约定，不会重新核查，所以写成事实的假设会变成后续一切工作的错误前提。交接前请先读一遍文档，把只是假设的内容降级为假设。

**为什么做成技能，而不是斜杠命令？**
两者都可行，适用场景不同。做成技能，它就和其他所有技能走同一套安装和更新路径，这正是它可分享的原因；智能体不会自行触发这个约束，是由 frontmatter 设定的，而不是由机制决定的。

## 生效标志

- 文档只是原对话的一小部分，规格、议题和差异在其中以路径和 URL 出现，而不是复制的正文。
- 不打开原会话，直接冷读这份文档，你也知道下一步该做什么。
- 新智能体直接开工，而不是让你重新解释 setup。
- 在分叉场景下，你回来时原会话还原样留在那里，没被动过。
- 推荐技能小节写出的正是你自己会用的技能。
- 里面没有任何密钥、令牌或密码。

## 它在整体中的位置

`handoff` 是一个**随时可用的独立技能 (reach-for-it-anytime standalone)**，位于会话之间的接缝处，而不是某条构建链内部，但适用面很窄。实话是，在阶段边界的五个选项里，你用它的频率会低于另外四个。它最近的邻居是 [prototype](https://aihero.dev/skills-prototype)，因为原型住在自己的目录里，一来一回正好是这个技能负责的那种跨越。当你在边界处不确定该继续、清空、交接、委派还是压缩时，[ask-matt](https://aihero.dev/skills-ask-matt) 里有给这五个选项排序的决策树，会带你走完其余技能。
