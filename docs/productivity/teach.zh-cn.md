## 它能做什么

`teach` 把你运行它的目录变成一个常设的教学工作区，并在多个[会话 (session)](https://www.aihero.dev/ai-coding-dictionary/session)中教你一个主题，每节课是短小自包含的 HTML 课程。

它不依赖[模型 (model)](https://www.aihero.dev/ai-coding-dictionary/model)已有的知识来教学。[参数化知识 (parametric knowledge)](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被视为不可信：在开讲之前，它会先去找高可信度的资料，记在 `RESOURCES.md` 里，并在每节课中引用这些资料。另一个结构性特点是它是[有状态的 (stateful)](https://www.aihero.dev/ai-coding-dictionary/stateful)：使命、资料、课程和你的学习记录都以文件形式住在目录里，所以下一次会话从这些文件继续，而不是靠上一段对话还剩多少上下文。

## 何时使用

输入 `/teach` 即可调用，[智能体 (agent)](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行调用。

当学习本身就是项目时用它：一门语言、一个框架、刚加入的代码库、瑜伽、着色器、考证。它不适合顺带解释一个概念的场景。

| 你想要什么 | 用什么 |
| --- | --- |
| 用几周时间学一个主题，多次会话逐步积累 | `teach` |
| 在当前会话里解释一个概念 | 直接在该会话里问 |
| 智能体的上一条消息没讲明白，换个讲法重讲 | [wait-what](https://aihero.dev/skills-wait-what) |
| 打磨已有的想法，而不是获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 让后台智能体读[一手来源 (primary source)](https://www.aihero.dev/ai-coding-dictionary/primary-source)，留下一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 在被追问中遇到不懂的东西，想学但不想打断[追问 (grilling)](https://www.aihero.dev/ai-coding-dictionary/grilling) | 用 [handoff](https://aihero.dev/skills-handoff) 交接到教学工作区，再在那里用 `teach` |

## 前提条件

`teach` 构建的是一个目录，而不是产出单个文件，而且一个工作区默认只承载一个使命，所以请在一个可以交给单个主题的地方运行它。不要放在你正在工作的项目里：推荐单独开一个仓库，而不是全局的 `~/.learnings/` 文件夹或工作项目本身。独立仓库还能让课程可以提交，团队就是这样分享课程的。

那个目录里会逐步积累这些内容：

| 路径 | 内容 |
| --- | --- |
| `MISSION.md` | 你为什么学这个。其他一切都挂在它上面；如果缺失，`teach` 首先会访谈你，直到把它补上 |
| `RESOURCES.md` | 教学依据的已审核来源，分知识 (Knowledge) 和智慧 (Wisdom，即社区) 两类 |
| `lessons/*.html` | 编号课程：教学的主要单元 |
| `reference/*.html` | 压缩的速查表、算法、术语表：你真正会反复查的文档 |
| `learning-records/*.md` | ADR 风格的记录，记下你已证明学会的东西，用于决定下一步教什么 |
| `assets/*` | 可复用组件，先从共享样式表起步，让课程看起来像同一门课 |
| `NOTES.md` | 你声明的教学偏好 |

关于这个列表，有两句实话。术语表适合多数主题，但技能自带的 `GLOSSARY-FORMAT.md` 已经不再被 `SKILL.md` 链接，所以只有你主动要求才会生成术语表（[issue #559](https://github.com/mattpocock/skills/issues/559)）。工作区也不总是建在你预期的位置，所以在长期课程上投入之前，先看下面的第一个问题。

## 要的是存储强度，而不是流利度

关键概念是**存储强度 (storage strength)**：长期保持，而**流利度 (fluency)** 是阅读当下的即时回忆，看似掌握，过一周就没了。`teach` 通过合意难度 (desirable difficulty) 来构建前者：提取练习 (retrieval practice)、间隔 (spacing)、交错 (interleaving)。知识先行，在理解阶段难度是敌人，因为它会吃掉理解所需的工作记忆；然后通过紧反馈循环来训练技能，这时难度就成了工具。

有两个因素决定你学到什么。**使命 (mission)**（你想学成的具体现实目标）锚定每一课；没有它，课程会飘向抽象，也没有东西能决定下一步讲什么。`teach` 根据使命和学习记录，在你的**最近发展区 (zone of proximal development)** 里选下一课：费力但够得着，不会超前到学不动。

这也是它会反驳你而不是一味顺从的原因。需要**智慧 (wisdom)**（现实判断）的问题，它会先尝试回答，再把你指向可以验证观点的社区。测验是门槛，不是形式：有用户报告说自己说了句“非常感谢”，还是被告知练习还没结束。

## 课程、参考文档和组件

一节**课程 (lesson)** 是一个自包含的 HTML 文件，短到一次能学完，紧扣使命，让你获得一个具体可感知的收获。它引用来源，推荐一篇值得你亲自去读的一手来源，并链接到兄弟课程和参考文档。

值得记住的区分是：课程很少被重读，参考文档会被反复查。所以一节课的压缩精华（语法表、算法、体式序列、术语表）应该放在 `reference/` 里，而不是埋在引入它的那节课里。

课程由 `assets/` 里的**组件 (component)** 搭建：样式表、测验组件、模拟器、图表 helper。默认复用。智能体在写课之前先读 `assets/`，基于已有组件搭建；凡是第二节课还可能用的新东西，都写成组件而不是内联。共享样式表是每个工作区挣到的第一个组件，它让输出不至于变成一堆一次性页面。

## 常见问题

**文件放在哪了？我的怎么进了 `~/.claude/skills`。**
这是真实存在的开放缺陷（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 里 `./` 同时指两个不同的根：`./MISSION-FORMAT.md` 及其兄弟文件确实就在已安装技能旁边的 `SKILL.md` 目录里，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 本意是放在你的目录里。把前者解析到技能安装目录的智能体，会顺手把后者也解析到那里，于是你的课程就写进了技能文件夹。继续搭建之前，先检查第一节课落在哪里，启动时明确说出目录名，不要依赖“当前目录”能被正确理解。

**我是留在同一个会话，还是每节课开新会话？**
三种做法都行：留在同一会话、在新会话里重新调用 `/teach`，或在同一文件夹里开新会话。每节课是一次独立调用。连续性靠文件夹，而不是靠对话。常见做法是在工作区开一个全新会话，说 `/teach next lesson for <topic>`。

**我怎么知道它教的不是现编的？**
只凭技能自己的保证，你无法知道。请去读一手来源。`teach` 不可靠到不能免检，任何基于大语言模型的技能都是如此。 grounding 机制（`RESOURCES.md`、每课的引用、每课推荐的一篇一手来源）是为了让核查变便宜，而不是免除核查。失败不是假设：有用户学 2x2 魔方时拿到了编造的公式，根本复原不了。遇到这类情况，按模型、运行环境、投入档位和来源四项排查。风险在记号精确的程序性领域最高，在输出可立即验证的地方最低，比如能运行的代码。

**测验正确答案永远是第一个选项。**
多人确认过，在 Sonnet、Opus 和 GLM 上都存在，至今未修。`SKILL.md` 现在要求每个选项字数相同，这消灭了另一种泄题（正确答案曾是唯一充分论证的选项），但对位置只字未提。有贡献者测试过指令层修复，报告九节课里 33 次正确答案还是落在 A 位（[#335](https://github.com/mattpocock/skills/issues/335)），这指向真正的修复应该是 `assets/` 里在渲染时洗牌的测验组件，而不是更好的措辞。在修复发布之前，请把答案位置当作无意义信息。`assets/` 目录属于你，要求加一个渲染时洗牌的组件是合理的本地修复。

**它默认我本来就会很多东西，还用没定义过的术语。**
这是最常见的实质性抱怨。没有水平评估环节：`teach` 从使命和学习记录推断你的水平，而第一节课时还没有学习记录。有用户把它接在 wayfinder 管线里，原话是：“它从没做追问来确定我的起点，所以默认了我本来就会很多。”还有人报告课程依赖未定义的术语，还有一节按用户硬件定制的课只讲硬件能做什么，从不讲它不能做什么。两件事有帮助：在第一条消息里写清已有基础和知识缺口；课程水平不对时大声纠正，因为纠正会变成学习记录，左右下一课。显式的知识评估环节是长期功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），尚未发布。

**它做间隔重复吗？它知道何时停吗？**
第一问是没有，第二问是不可靠。间隔和交错是课程设计依据的原则，但没有任何排期复习的机制，也没有 Anki 或日历集成，两者都是反复出现的需求。相关的缺口是退出标准：有用户说，`teach`“擅长产出下一课，不擅长判断何时停下来复习或做真实练习。”如果你想要复习或练习而不是新内容，请直接说，技能不会主动提议切换。

**它只对写代码有用吗？**
不是，非代码用途反而是记录里更大的部分：韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影剧情、Azure 和 CCNA 考证、大学考试，还有八岁和十岁孩子用的密室逃脱和火蜥蜴可打印读物。技能里没有任何编程专属的东西：使命、资料、最近发展区和练习在任何领域都一样。在代码领域，报告最多的强用法不是从零学语言，而是在陌生代码库或新团队技术栈里快速定向。

**该用什么模型跑它？**
没有标准答案，报告中的差异很大。有报告称更高的[推理投入 (effort)](https://www.aihero.dev/ai-coding-dictionary/effort)比中等档位产出的课程明显更好。有用户用 Copilot CLI 接 Codex 跑同一个技能，只得到一张 30 行的 HTML 卡片，而 Claude Code 产出的是完整课程。它可以在 Claude Cowork 里原样运行，前提是你的组织允许在那里添加技能。如果课程偏薄，先换模型、[运行环境 (harness)](https://www.aihero.dev/ai-coding-dictionary/harness)或投入档位，再改提示词。

## 生效标志

- 在空目录里，它首先访谈你为什么学这个，而不是直接产出课程。
- `RESOURCES.md` 先于课程被填满，每节课都有一篇值得亲自去读的一手来源。
- 课中的断言带有外部链接。没有引用的课程就是在凭记忆教学。
- 一节课一次能学完，学完你能做到一件之前做不到的事。
- 在文件夹里开全新会话，说一句“下一课”，课程能继续而不是重开。
- `learning-records/` 在增长，课程不再重复教你已证明掌握的东西。
- 课程看起来像同一门课：它们链接 `assets/` 里的样式表，而不是各自内嵌样式。
- 需要判断力的问题会把你指向论坛、subreddit 或课程，而不只给一个答案。

## 它在整体中的位置

`teach` 是一个**随时可用的独立技能 (reach-for-it-anytime standalone)**。它不是构建链中的一步，也不和工程流程共享产物；它拥有自己的目录，主题持续多久，它就住多久。

它唯一真正的邻居是 [handoff](https://aihero.dev/skills-handoff)，组合方式是 Matt 用来回答“被追问到不懂的东西怎么办”的那句：不要停下追问去学，用 `/handoff` 交接到教学工作区，在那里用 `/teach` 学完，再回去接着原来的追问。附近的替代选项是 [research](https://aihero.dev/skills-research)，当你想要的是一份带引用的文档，而不是课程和长期保持时。当你不确定哪个技能或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会带你走完整个集合。
